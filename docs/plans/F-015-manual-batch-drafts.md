# Plan F-015: Manual batch reply drafts

- **Spec:** [F-015](../specs/F-015-manual-batch-drafts.md). **Status:** Not started (spec is Draft).
- **Blocked by:** spec approval by the user; the user's answers to Q1 to Q3 (requirements amendment, stateful-backend ADR, OpenAI model and budget); the accepted ADR for the stateful backend before step 4 (the rate-limit table); F-012 merged before step 9 (UI). Steps 1, 2, 3, 5 and 7 do not wait for F-012.
- **Branch:** `f-015-manual-batch-drafts`, created from `main` after F-012 is merged, or from `main` now for the backend steps and rebased before step 9 (the orchestrator decides). Never work on the F-012 prototype branch.
- **Rule reminders:** never `Mail.Send`; never `/send`, `/reply`, `/replyAll`, `/forward`; no email content in logs, storage or the database; no secrets in the client or the repo; no new platform; AI output is plain text only; every Graph member, endpoint and permission used must match the spec's cited page.

## Dependency decisions (needs the user's yes before step 4 and step 6)
| Dependency | Where | Why | Notes |
|---|---|---|---|
| A Postgres client for Deno (Postgres.js or Deno Postgres from npm, exact version) | `supabase/functions` | The function reaches the private schema through `SUPABASE_DB_URL`; `supabase-js` goes through the Data API, which the `private` schema is not exposed to | Supabase's page lists both clients as allowed. The coder proposes one with its exact version; the orchestrator confirms. |
| None for OpenAI | `supabase/functions` | Plain `fetch` to the OpenAI REST API is enough for one structured call | Avoids a heavy dependency (CLAUDE.md rule 8) |
| None in the add-in | `src/` | Graph is called with `fetch`; MSAL is already a dependency | No Graph SDK |
