## Dependency decision (needs no ADR)
`@fluentui/react-icons` is re-added as a **direct** dependency, exact version `2.0.344`, the version already in `package-lock.json` and `node_modules` (it is a dependency of the Fluent component packages). Reason: the redesign imports icons directly, and importing a package that is only present transitively breaks when the transitive range changes. F-001 removed the direct dependency because nothing used it. Per-icon named imports keep the bundle small, and no new package enters the lockfile, so this is not a "heavy dependency" under CLAUDE.md rule 8. No other dependency is added (an `axe-core` dev dependency is spec Q14 and needs a separate yes).

## Prototype brief (step 1, throwaway)
- **What:** one page (`prototype.html` entry) with a toolbar that switches Direction (A, B, C), accent (navy, orange), theme (light, dark, and forced high-contrast), width (320, 360, 450, 500 px, shown in a resizable frame), and state. Not shipped, not in `dist/`, not merged.
- **Reference:** render the user's mockup adapted to the brand as Direction A: header; Analisar/Responder tabs (no Escrever in read mode); message strip; Resumo inteligente with 3 bullets and the three chips; Detalhes extraídos rows; Resposta sugerida with the primary button "Abrir resposta para revisão" and the secondary "Regenerar" and "Ajustar tom"; Ferramentas rápidas tiles; the assurance line; the footer status. Then B and C with the same content.
- **Must show, at 320 px and 450 px, in light and dark:** the production pane (header, message, comingSoon card, assurance, footer) and the full layout (every slot), for each direction; for A also both accents (A-navy, A-orange with the darker orange and the mockup orange side by side so the contrast difference is visible).
- **States:** message ready; loading (Skeleton); no message; body error; backend connecting, connected, needSignIn, error, unsupported, notConfigured; a stress case with a 200-character unbroken subject, a 120-character address and a long body; an RTL subject.
- **Rules for the prototype:** real Fluent v9 components and the real theme code path (`createLightTheme`, `createDarkTheme`, `FluentProvider`) so the result predicts the shipped look; fake, obviously fake sample text (no real email, no real names or addresses); no Office.js, no MSAL, no `fetch`; fonts as in the spec (system fonts only); clearly labelled "PROTOTYPE" in the page so it is never mistaken for the product.
- **Deliverables:** how to run it, which file holds each direction, and a table of the measured contrast for every semantic pair (MessageBar intents, chip colors, status icons) in both themes. Screenshots are optional and go to the scratchpad, never to the repo.
- **Decision recorded here after the review:** direction ___, accent ___, icon ___, language ___, tabs ___, production visibility ___.
