# Plan F-016: Per-user style profile

- **Spec:** [F-016](../specs/F-016-style-profile.md). **Status:** Not started (spec is Draft).
- **Blocked by:** spec approval; the **accepted ADR for the stateful backend** (D13; no migration before it); F-015 steps 3 (shared auth module) and 4 (private schema, database helper, rate-limit counter) merged; F-012 merged before step 8 (UI); the DPO's answers P1 to P3 before the profile is used with real customer mail (tests with the user's own sample data do not wait for it).
- **Branch:** `f-016-style-profile`, created from `main` after F-015 steps 3 and 4 are merged.
- **Rule reminders:** no email text in the database, logs or browser storage; no write scope in the F-016 pane code; the profile is never part of the system prompt; the `oid` always comes from the validated token; every query is parameterized and filtered by `oid`.

## Dependency decisions
None new. The function reuses the Postgres client chosen in F-015 step 4. No OpenAI SDK, no embeddings, no fine-tuning call.
